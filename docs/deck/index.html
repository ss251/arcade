The problem

Everyone has agent capacity they can't sell.

You have a skill that produces genuinely good output — a research routine, a due-diligence brief, a data check. It's worth nothing to anyone but you, because the only way to share it is to hand over the prompt and the API key.

Meanwhile the buyer's problem is the mirror image: an agent is capped by whatever tools its operator already paid for. Subscriptions can't fix that — a card transaction costs ~30¢, so nobody can bill you $0.0004 for one call. They have to sell you a $20/month bucket you underuse.

An agent doesn't need a card. It needs an endpoint and a balance.

How it works

One command turns a skill into revenue.

 SELLER (own machine)              ARCADE                    BUYER (any agent)
┌──────────────────────┐  ┌────────────────────────┐  ┌────────────────────┐
│ skill/ or agent/     │  │ REGISTRY               │  │ Circle agent wallet│
│  prompts, code, keys │  │  listings · price      │◀─│  or EOA            │
│  NEVER LEAVE ────────│──│  ratings · SLA         │  │                    │
│                      │  ├────────────────────────┤  │ probe → 402 → sign │
│ RUNNER (daemon)      │◀─│ /x/:seller/:skill      │◀─│ → retry → poll     │
│  outbound wss only   │──│ paywall→broker→settle  │──│                    │
│  sandbox per job     │  └────────────────────────┘  └────────────────────┘
└──────────────────────┘        settles on Arc testnet

The runner dials out and pulls work, so a seller runs from a laptop behind NAT with no open ports — and the hub structurally cannot receive their credentials, because nothing of theirs is ever transmitted.

Settlement happens only on success. Payment is verified before the seller does any work, and the authorization is cashed only after the output validates against the listing's schema. A refusal, timeout, bounds breach or malformed result leaves it unbroadcast. That is the refund — the buyer pays nothing.

The two-machine run matters more than the rest. On one host, "seller code never leaves the seller's machine" is unfalsifiable. So it was run with the hub on one box and the runner on another over Tailscale — the runner working from a fresh clone — asserting afterwards that the hub held no engine config, entry path, or egress rule.

Since Checkpoint 2 the whole pipeline moved from dev runs to a deployed marketplace: the hub is live on a public URL, its first sale settled through the fee-splitter contract, and the receipt — hash, split, latency — is served by the hub itself at /receipts.

The guarantee

The hub cannot see your skill. Structurally.

Published

  • name, description, tags
  • price and work bounds
  • input / output schemas
  • ratings and measured SLA

Never transmitted

  • engine and entry point
  • system prompt
  • secret names, egress rules
  • the code itself

This isn't a filter someone could forget to call. The public projection is a type with nowhere to put a prompt or a key, so leaking one is a compile error — and a property test asserts it over arbitrary generated manifests, checking that no canary value survives to the wire.

Rigor

Where the bodies were found.

498TypeScript tests
13Foundry tests
12audit agents
6convergent defects

The fee-splitter contract was audited before deploy. Twelve independent agents converged on one root defect — a seller parameter unbound to anything the buyer signed — and the contract's own docstring claimed a bound that was measurably false. It was rewritten so the whole class is unrepresentable rather than merely guarded.

The best catch would have cost a day: TransferWithAuthorization and ReceiveWithAuthorization carry different EIP-712 typehashes. Every settlement would have reverted on an invalid signature — and the probe script that "confirmed" it worked had only ever tested a garbage signature.
