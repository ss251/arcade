## Result interpretation

Match job/skill/amount/buyer/seller/network/rail and the actual signed nonce against
the terminal receipt. Validate statuses, integer money and basic receipt scalars.
Only a matching succeeded+settled result is eligible for output. Nonsettled
succeeded is possible after rail failure; never expose unpaid output or repeat
the producer's unsafe no-charge sentence.

Ordinary pipeline.ts currently omits optional settleRefKind. Allow true absence
with an exact retained rail and valid reference shape; reject contradictory or
malformed presence. EIP3009 requires a nonzero hash and uses the existing qualified
txLink. Gateway requires a UUID and is only hub-reported transfer acceptance,
not a mined batch or available credit. This is not independent chain verification.
Ignore raw provider detail, unrecognized receipt fields and supplied explorer URLs.
