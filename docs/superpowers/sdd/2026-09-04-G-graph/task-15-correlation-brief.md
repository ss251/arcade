# G15K — correlate retained query evidence

Release the Graph harness/tests, Graph client's shared header/body decoders,
an inert alias of the consumer's existing identity-ID selector, and plan-owned
brief/report/index/progress. Reuse original validation bodies mechanically;
preserve original signing, validity/cap/nonce/replay and transport sequencing.
No additional payer, endpoint, key mechanism or live command is released.

Read only bounded private captures with current source/query binding. Correlate
the initial402, pre-sign chain/time observations, fixed declared forward intent,
single paid response, post-payment chain/receipt/block RPC sequence and original
paid data. Receipt evidence is independent of Graph result metadata. A second
query must derive exact sorted IDs and block from a retained first-query result;
its RPC IDs may continue the original factory or start at1 after a cached first
query in a new factory. Neither case permits a repeated paid request.

This checkpoint establishes retained protocol consistency, not authenticated
network acquisition, an owner signature, independent consensus or global cache/
spending authority. Synthetic positive records stay explicitly declared data.
All writes, cache commits, reservation reconciliation and live integration are
separate later work. Failures never retry, refund or overwrite evidence.

Use offline TDD including rehashed wrong protocol/receipt/intent relationships,
null receipt polling, malformed or incomplete records, parent/second-query
binding, no-key readback and source changes. One sequential four-worker full
gate after focused tests/strict, one atomic commit and exact-one mainFF. No push,
real endpoint/key/payment or change to existing owner pauses.
