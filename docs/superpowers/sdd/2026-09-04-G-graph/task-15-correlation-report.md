# G15K retained protocol correlation

The [correlation brief](task-15-correlation-brief.md) releases a read-only
correlator over the existing bounded private capture reader. This is not a live
G15 run, cache admission, reservation reconciliation or an owner signature.
Positive fixed-owner captures are declared synthetic protocol data. A coherent
forgery by the local file owner can pass; hashes detect accidental alteration,
not malicious acquisition claims or independent chain consensus.

The verifier joins the exact source/query binding, initial402 and original
challenge rules, pre-sign Base chain/block-time observations, retained fixed
forward intent, one paid200 response and original settlement header, post-paid
Base chain/receipt polling/block requests, original token/transfer/nonce receipt
rules and original paid-body validation. RPC request hashes are reconstructed
from the exact JSON field order, IDs, methods and parameters used by the client.
Unexpected, missing or trailing records refuse; null polling cannot exceed the
bounded retained sequence. Encoding/length/redirect/body bounds are checked.

Returned result data is bounded by the consumer's existing plain-data copier
and deeply frozen. Evidence includes original transaction/cost, receipt block,
source/query/capture/forward digests, capture times and RPC ID range. These are
private records, not a public provider dump. Graph result metadata remains
distinct from the transaction receipt block; paid results with incomplete Graph
metadata remain paid data, not automatically trusted facts or another query.

A second query requires an original verifier-produced first-query handle, fresh
readback of its unchanged capture and matching current-source binding. The
consumer's original selector supplies the exact sorted unique agent IDs and
first Graph block hash. Empty/incomplete/foreign first results cannot authorize
that follow-up. A second nonce and payment transaction must be distinct. RPC IDs
either continue the original factory or restart at1 for a new factory after
partial-cache reuse; no factory is actually created here. The recorded sequence
must fit the existing80s consumer budget, with the first capture as origin for
same-factory continuation. Five-second local read/verification bounds include
parent revalidation; synchronous filesystem work is not kernel-preemptible.

No existing validity constant, cap, replay protection, nonce/signature rule or
transport order changed. Mechanical reversal of the three shared decoder moves
restores the entire original client; deleting the inert ID-selector alias
restores the entire consumer; removing the new verifier/imports restores every
existing harness byte. Original source SHA256s:
