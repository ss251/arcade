## 1. The project, as built (builder view)

ARCADE = a marketplace where anyone publishes an **agent skill as a paid x402 endpoint on Circle's Arc L1**, and buyer agents pay per call in USDC. Repo: `github.com/ss251/arcade` (this checkout). 112 commits, 2026-07-25 → 2026-08-07, built solo for the Encode × Circle Arc hackathon (accelerator-seat prize, no cash).

Trust order (docs/architecture.md): `verify payment → execute in seller sandbox → validate output against listing schema → settle`. Settlement is EIP-3009 `transferWithAuthorization` on Arc USDC, signed offline by the buyer, broadcast by the hub's facilitator key only after schema-valid, non-refused, non-empty output. Failure = the authorization is never broadcast. The result is released only against a **settled** receipt (T-PRIV-002). The 402 advertises `x-arcade-payment.settlement: on-validated-output` because x402 has no failure semantics (README "Discovery").

Secrecy boundary (packages/core/src/manifest.ts): `toPublicListing` constructs a public type with nowhere to put `engine.*`, `secrets`, `entry`, `systemPrompt`, `egress`. Property test `packages/core/test/secrecy.property.test.ts`. Runner is pull-model (outbound wss, no open ports). Proven across two machines over Tailscale (README).

Agents hiring agents: a skill declaring `hire-skills` gets a `hire_skill` tool; the **runner** (not the sandbox) holds the sub-purchase key and enforces `maxSubSpendUsd` in `packages/runner/src/hire-broker.ts` over a Unix socket with a per-job HMAC token; absent bound = zero; hired results come back fenced. Live listing `wallet-risk-note` buys `usdc-flow-check` mid-run ("each call settles twice"). **Known gap T-SPEND-003** (docs/threat-model.md): a hire carries `{skillId,input,maxAmountUsd}` and no lineage; hub cannot tell a sub-hire from a buyer call; `A→B→A` loops settle real USDC each hop; residual **High once a second hiring skill lists**. The stated fix is a hop count + ancestor set in the 402 request metadata, refused at the paid endpoint (`apps/hub/src/server.ts:771` region), pass-through in the broker.

Other facts: Rail service `packages/payments/src/rail.ts:56-68` (`challenge/verify/settle`), rails EIP3009Live (proven), GatewayLive (Circle Nanopayments, code-complete, never proven live on Arc), RailTest. FeeSplitter.sol deployed on Arc testnet `0xf95c8afefae677fdcfc7bd5b8aaaf3702db99206`, 5% fee, `withdrawFees()` permissionless; receipt `feeSweepTx` backfill exists but has no production caller. Ratings: EIP-191 signature over `ratingDigest(jobId, stars)` recovering to the receipt's buyer, only for settled receipts. Objective stats (success rate, p50/p95, availability) computed from receipts. Identity today: seller = address that EIP-191-signs the websocket Hello; buyer = EIP-3009 payer. Engines: `script`, `claude-api`, `claude-agent`. Sandbox = scrubbed env + Scope-managed process (not a container). Live hub: `https://arcade-hub-production.up.railway.app` (200 on /healthz on 2026-09-04). Tests: 475/480 vitest + 25/27 bun (all 7 failures are spawn timeouts on the dev host). Web app `apps/web`: one page, chat + sidebar, browser-signed EIP-3009, key-less settle courier. On-chain evidence in README: `0xc9b77c1e…` (EIP-3009, 87,153 gas, 0.002179 USDC), `0x5eb961c0…` (full loop), `0xf45de149…` (two machines).

Vision documents (internal, private, summarized): the pivot of 2026-07-24 chose "C6 skills-as-endpoints" over a spend-firewall product because Arc had **zero real paid sellers** and the marketplace makes supply creation a one-command act; framing "agents hiring agents" kills the "plumbing" objection; locked D1 flat per-call prices with `replaces: "$X/mo seat"` economics, D2 settle-on-success, D3 BYOE self-hosted runners only, D4 platform fee from day one. Earlier research found the empty lane on Arc was **containment** ("agents that cannot drain"): none of Circle's sample apps had spend caps; Circle agent-wallet policies were mainnet-only; per-wallet caps are commodity, the missing layer is fleet/tree-scoped budgets + kill switch. The hire broker is that DNA surviving inside the marketplace. Video narration (docs/narration) leads with: "the only way to sell a skill today is to hand over your prompt and API key"; "nothing to refund because nothing was taken"; "one buyer action, two settlements".

## 5. Questions the debate must answer (from builder, user, market perspectives)

1. **Builder:** Is hop lineage + tree budget the right P0, and what exactly should be in the 402 metadata and the receipt so a stranger can verify the tree on Arcscan? Is "caps only shrink" enforceable given each hop is an independent EIP-3009 authorization from the *seller's* sub-buy wallet (i.e. the buyer's cap is not the money that moves at hop 2)? What is the honest claim?
2. **Builder:** Given ERC-8004 registries are on Arc testnet and The Graph indexes arc-testnet, should ARCADE (a) register sellers in the Arc IdentityRegistry and write **settlement-tied** ReputationRegistry feedback from the hub (the "receipt, not badge" the market asks for), (b) deploy the Agent0 subgraph to arc-testnet in Studio and use it as the marketplace's live discovery/reputation query — making The Graph load-bearing on Arc itself instead of only via the Base x402 hop? Or is the arXiv Sybil finding decisive against touching 8004 at all? Which is stronger for the Graph judges: the Base x402 cost-of-goods skill, the Arc 8004 subgraph, or both?
3. **User (buyer agent / seller):** What does a buyer agent actually need before paying a stranger — a pre-pay probe, a signed sample, ENS-locked payTo, human-backed (World) sellers, reputation? Which single addition most reduces the "paid, got 400 / paid a dead endpoint" complaint on X? What does a seller need to trust listing on ARCADE over Bazaar/Circle Marketplace?
4. **Market:** Mars already won the Arc agentic prize with an "audited skills marketplace". AgentForge did skills-on-Arc in April. How does ARCADE differentiate in one sentence a judge and CT will both accept, with evidence? Which of the three "trust families" (off-chain refund / escrow / never-capture) wins the argument, and how should the video state it?
5. **Prizes:** Arc + Graph + ENS ($500) vs Arc + Graph + World ($3,500). Expected value vs coherence. Is there a way ENS earns its day (e.g. ENSIP-25 record pointing at the Arc ERC-8004 id, closing the identity loop across chains)?
6. **Risk:** Everything demoed is testnet except the Graph hop. Arc mainnet lands Sept 16, after the deadline. What is the credible "deployment-ready by Sept 30" story and what must be true in the repo for a judge to believe it?
7. **Scope:** 8 solo build days. What is cut first if behind? What is the minimum that still wins each of the three partner prizes?
