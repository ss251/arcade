# Plan D — ERC-8004 on Arc, all three registries (M4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every ARCADE listing a real on-chain identity on Arc, and turn each terminal job into ERC-8004 evidence: the hub's operator key requests validation, its validator key answers `100` on settle and `0` otherwise, and its attester key writes feedback carrying the settlement tx as `proofOfPayment` — all best-effort, none of it able to change a settlement outcome.

**Architecture:** Three seams. (1) The **seller's machine** owns the identity: `arcade identity register <skill>` mints the ERC-721 with the seller's own key, stores the `agentId` in `~/.arcade/config.json`, and approves the hub's operator with `setApprovalForAll` — the hub never sees a seller key, exactly as with engine config. (2) The **hub** serves the two off-chain documents the registries point at (`agent-registration.json`, and the per-job request/response/feedback docs) and holds the three hub keys. (3) A **best-effort queue** hangs off `apps/hub/src/pipeline.ts` after `putReceipt` (line 92) via `Effect.serviceOption`, so a hub with no ERC-8004 keys runs unchanged and a failing registry never blocks, delays or reverses a settlement.

**Tech Stack:** Bun 1.3, TypeScript, Effect 3.22 (`Effect.gen`, `Schema.Class`, `Data.TaggedError`, `Queue`, `Schedule`), viem 2.x, vitest 3 (`*.test.ts`) + `bun test` (`*.bun.test.ts`), `bun:sqlite` write-through store.

## Global Constraints

- Never commit `internal/`. No secrets in source or `.env` — `ARCADE_OPERATOR_KEY`, `ARCADE_VALIDATOR_KEY`, `ARCADE_ATTESTER_KEY` come from env/Keychain only, and are never logged, never returned by an endpoint, and never sent to a runner.
- **Depends on / rebase base (spec §13).** This stream starts **Sun Sept 7** in parallel with B, C, E and G. It depends on **Plan A only** (`loadChainConfig`/`ChainConfig.erc8004` from Plan A Task 10, `RunJobArgs` and `Store` from Plan A Tasks 5–6, plus the pre-existing `explorerTxUrl`/`ARC_CHAIN_ID` which Plan A rebases onto `ChainConfig`). Branch from `main` after Plan A Task 12 lands; rebase onto `main` before each merge. Canonical merge order for shared files is **A → B → C → D → E → F → G → H → I**, so rebase `apps/hub/src/store.ts`, `pipeline.ts`, `server.ts` and `ui.ts` onto Plan C's canary work, and `packages/runner/src/cli.ts` onto Plan B's rewritten `publish` dispatch, before landing.
- **Field ownership.** This plan owns four `ListingRecord` fields and every downstream consumer must use these exact names: `agentId`, `registrationTx`, `agentVerified`, `ensName` (declared here, **written by Plan E**). Per-agent counts are *not* stored on `ListingRecord` — they are read at request time from `Erc8004.evidenceFor(agentId)` as `AgentEvidence {validationPasses, validationsRead, settlementFeedback, stale}` and surfaced only under the `erc8004` key of `GET /listings/:id` (Task 12). There is no `identityTx`, no `registrationUri`, no `validationPassCount`, no `validationTotalCount` and no `feedbackCount` on a listing; a plan that renders those names is renaming this plan's interface and is wrong.
- **Settle only on success.** ERC-8004 writes are side effects that happen *after* the receipt is persisted; they never change a settlement outcome, never delay one, and a registry failure never marks a receipt unsettled.
- Never call `waitForTransactionReceipt` against Arc's public RPC — one receipt read per tick with `Effect.retry` + `Schedule.spaced`, exactly as `packages/payments/src/eip3009.ts:374-383` does (the `-32011 request limit reached` fix).
- Money is 6-decimal atomic `bigint`; **gas is 18-decimal native USDC** (`packages/core/src/chain.ts:28-34`). The gas check in Task 3 is the only place this plan touches 18-decimal values, and it never enters a receipt.
- Effect idioms only: `Effect.gen`, `Schema.Class`, `Data.TaggedError`, `Context.Tag`/`Layer`. Effect Schema, never zod.
- Third-party x402 clients (Circle CLI) must keep working: this plan adds no required header and changes no 402 challenge.
- **Never `getSummary`** on either registry — neither `ReputationRegistry.getSummary` nor `ValidationRegistry.getSummary`. Both aggregate over clients ARCADE did not vet; the only honest count is one filtered to our own attester/validator. Never present ERC-8004 evidence as a score, and never gate a purchase on it.
- Gates before each commit: `bun run test` (vitest + bun), `bunx tsc --noEmit` (or `bun run typecheck`). No web or contract changes in this plan, so `bun run web:build` and `forge test` are unaffected.
- Conventional, small commits; one per task.
- Everything demoable on Arc testnet (chain 5042002) against the live hub `https://arcade-hub-production.up.railway.app` or a local hub per `docs/runbook.md`.

 * ERC-8004 on Arc.
 *
 * Every fragment below is pinned from two sources that agree:
 *  - the ERC text (github.com/ethereum/ERCs/blob/master/ERCS/erc-8004.md), and
 *  - Circle's deployed-contract tutorial (docs.arc.io/arc/tutorials/register-your-first-ai-agent),
 *    which is the authority for what is actually at the three 0x8004… addresses on Arc testnet.

 * They are `as const` and exported from ONE place because the same call is encoded on the
 * seller's machine (register, setApprovalForAll) and on the hub (validation, feedback). Two

 * against a deployed registry surfaces as a revert with no message.

/**
 * A hash of a JSON value that commits to the bytes, not to an object.
 *
 * The registries store a `bytes32` next to a URI, and the whole point is that a reader can
 * fetch the URI and check it. So the hash MUST be over exactly the bytes the endpoint
 * serves — hence `docBytes` (compact `JSON.stringify`, no pretty printing) as the single
 * definition, used both to hash and to respond.
 */
export const docBytes = (doc: unknown): string => JSON.stringify(doc)
export const docHash = (doc: unknown): `0x${string}` => keccak256(toHex(docBytes(doc)))
export const hashJson = (value: unknown): `0x${string}` => keccak256(toHex(JSON.stringify(value ?? null)))

/**
 * The file `IdentityRegistry.register(agentURI)` points at.
 *
 * Served over https by the hub rather than pinned to IPFS. The ERC takes any URI (the Arc
 * tutorial's `ipfs://` is an example, not a requirement), and `active` has to be able to
 * change when a runner goes offline — an immutable pin would advertise a dead endpoint
 * forever, which is the opposite of what liveness means here.
 */
export const buildAgentRegistration = (input: AgentRegistrationInput): AgentRegistrationDoc => {
  const origin = trimOrigin(input.origin)
  const doc = {
    type: "AgentRegistration" as const,
    version: "1" as const,
    name: input.serviceName,
    description: input.description,
    active: input.active,
    x402Support: true as const,
    agentRegistry: caip10(input.chainId, input.identityRegistry),
    agentAddress: caip10(input.chainId, input.seller),
    endpoints: [
      { name: "x402", endpoint: `${origin}/x/${input.seller}/${input.skillId}`, version: "1" },
      { name: "mcp", endpoint: `${origin}/mcp`, version: "1" },
      { name: "openapi", endpoint: `${origin}/openapi.json`, version: "1" },
      { name: "web", endpoint: `${origin}/skill/${input.skillId}`, version: "1" }
    ],
    supportedTrusts: [ARCADE_SUPPORTED_TRUST],
    ...(input.ens === undefined ? {} : { ens: input.ens })
  }
  // `input` is non-enumerable so it never reaches the wire or the hash: the document is
  // exactly the fields above, and carrying its own arguments would change the bytes.
  return Object.defineProperty(doc, "input", { value: input, enumerable: false }) as AgentRegistrationDoc
}

/**
 * ERC-8004 writes and reads, one key per role.
 *
 * THREE KEYS, because the standard requires three distinct standings and one key cannot
 * hold them all:
 *  - `ARCADE_OPERATOR_KEY` is approved by the seller with `setApprovalForAll`, which is
 *    what lets it call `validationRequest` (the ERC: "MUST be called by the owner or
 *    operator of agentId").
 *  - `ARCADE_VALIDATOR_KEY` is the address named in the request, and is the only address
 *    the registry will accept a response from.
 *  - `ARCADE_ATTESTER_KEY` writes feedback, and MUST be neither owner nor operator — the
 *    ERC forbids self-dealing, and the Arc tutorial uses a second wallet for exactly this.
 *
 * Collapsing operator and attester into one key would make every feedback write revert, and
 * it would deserve to: it would be the seller's own agent rating itself.
 */

  readonly reason: string
}> {}

/** Same `-32011` shape as `packages/payments/src/eip3009.ts:103`. Arc's public RPC rate-limits. */
const isRateLimit = (e: unknown): boolean => {
  const m = String((e as { message?: string })?.message ?? e)
  return m.includes("request limit") || m.includes("-32011")
}
const rpcRetry = Schedule.exponential("750 millis").pipe(Schedule.jittered, Schedule.compose(Schedule.recurs(4)))

/** How long an evidence read is reused. A listing page must not be an RPC burst. */
const EVIDENCE_TTL_MS = 60_000
/** Statuses read per agent. `getAgentValidations` is unbounded; this read is not. */
const EVIDENCE_MAX_VALIDATIONS = 20

export const keyRoleRefusal = (a: { operator: string; validator: string; attester: string }): string | undefined => {
  const lower = (s: string) => s.toLowerCase()
  if (lower(a.attester) === lower(a.operator)) {
    return `ARCADE_ATTESTER_KEY and ARCADE_OPERATOR_KEY are the same address (${a.attester}). ERC-8004 forbids feedback from an agent's owner or operator, so every giveFeedback would revert. Use three separate keys.`
  }
  if (lower(a.attester) === lower(a.validator)) {
    return `ARCADE_ATTESTER_KEY and ARCADE_VALIDATOR_KEY are the same address (${a.attester}). Keep the address that judges and the address that vouches distinct — one key doing both is one signature to forge.`
  }
  if (lower(a.operator) === lower(a.validator)) {
    return `ARCADE_OPERATOR_KEY and ARCADE_VALIDATOR_KEY are the same address (${a.operator}). The requester and the responder would be one party, which makes the validation record say nothing.`
  }
  return undefined
}

export interface MakeErc8004 {
  readonly registries: { identity: string; reputation: string; validation: string }
  readonly chainId: number
  readonly reader: Erc8004Reader
  readonly operator: Erc8004Wallet
  readonly validator: Erc8004Wallet
  readonly attester: Erc8004Wallet
  readonly nowMs?: () => number
}

export const makeErc8004 = (cfg: MakeErc8004): Erc8004 => {
  const now = cfg.nowMs ?? (() => Date.now())

  const write = (op: string, w: Erc8004Wallet, args: unknown) =>
    Effect.tryPromise({
      try: () => w.writeContract(args),
      catch: (e) => new Erc8004Failed({ op, reason: String((e as Error)?.message ?? e) })
    }).pipe(Effect.retry({ schedule: rpcRetry, while: (e) => isRateLimit(e.reason) }))

  const read = <A>(op: string, args: unknown) =>
    Effect.tryPromise({
      try: () => cfg.reader.readContract(args) as Promise<A>,
      catch: (e) => new Erc8004Failed({ op, reason: String((e as Error)?.message ?? e) })
    }).pipe(Effect.retry({ schedule: rpcRetry, while: (e) => isRateLimit(e.reason) }))

  const cache = new Map<string, { at: number; value: AgentEvidence }>()

  return {
    armed: true,
    addresses: { operator: cfg.operator.address, validator: cfg.validator.address, attester: cfg.attester.address },
    registries: cfg.registries,

    ownerOf: (agentId) =>
      read<string>("ownerOf", {
        address: cfg.registries.identity,
        abi: IDENTITY_REGISTRY_ABI,
        functionName: "ownerOf",
        args: [BigInt(agentId)]
      }),

    requestValidation: (a) =>
      write("validationRequest", cfg.operator, {
        address: cfg.registries.validation,
        abi: VALIDATION_REGISTRY_ABI,
        functionName: "validationRequest",
        args: [cfg.validator.address, BigInt(a.agentId), a.requestURI, a.requestHash]
      }),

    respondValidation: (a) =>
      write("validationResponse", cfg.validator, {
        address: cfg.registries.validation,
        abi: VALIDATION_REGISTRY_ABI,
        functionName: "validationResponse",
        // `tag` is fixed: everything this validator says is about one question — did the
        // settlement happen. A per-call tag would invite reading it as a category.
        args: [a.requestHash, a.response, a.responseURI, a.responseHash, ARCADE_VALIDATION_TAG]
      }),

    giveFeedback: (a) =>
      write("giveFeedback", cfg.attester, {
        address: cfg.registries.reputation,
        abi: REPUTATION_REGISTRY_ABI,
        functionName: "giveFeedback",
        // value 1 / decimals 0 — binary "a payment settled", never a score.
        args: [BigInt(a.agentId), 1n, 0, ARCADE_FEEDBACK_TAG1, a.skillId, a.endpoint, a.feedbackURI, a.feedbackHash]
      }),

    /**
     * Two facts, both filtered to keys we hold, both bounded.
     *
     * Never `getSummary`: it averages over every client that has ever written, so anyone
     * can move it, and a marketplace quoting it would be quoting strangers. `readAllFeedback`
     * filtered to our attester answers a question we can defend — how many settlements this
     * hub has vouched for — and `getAgentValidations` + `getValidationStatus` does the same
     * for validation, capped so one agent with a long history cannot turn a page render into
     * hundreds of RPC calls.
     */
    evidenceFor: (agentId) =>
      Effect.gen(function* () {
        const hit = cache.get(agentId)
        if (hit !== undefined && now() - hit.at < EVIDENCE_TTL_MS) return hit.value

        const result = yield* Effect.gen(function* () {
          const hashes = yield* read<ReadonlyArray<string>>("getAgentValidations", {
            address: cfg.registries.validation,
            abi: VALIDATION_REGISTRY_ABI,
            functionName: "getAgentValidations",
            args: [BigInt(agentId)]
          })
          const recent = hashes.slice(-EVIDENCE_MAX_VALIDATIONS)
          let passes = 0
          for (const h of recent) {
            const st = yield* read<readonly [string, bigint, number, string, string, bigint]>("getValidationStatus", {
              address: cfg.registries.validation,
              abi: VALIDATION_REGISTRY_ABI,
              functionName: "getValidationStatus",
              args: [h]
            })
            if (st[0].toLowerCase() === cfg.validator.address.toLowerCase() && st[2] === 100) passes++
          }
          const fb = yield* read<readonly [ReadonlyArray<string>, ...ReadonlyArray<unknown>]>("readAllFeedback", {
            address: cfg.registries.reputation,
            abi: REPUTATION_REGISTRY_ABI,
            functionName: "readAllFeedback",
            args: [BigInt(agentId), [cfg.attester.address], ARCADE_FEEDBACK_TAG1, "", false]
          })
          return {
            validationPasses: passes,
            validationsRead: recent.length,
            settlementFeedback: fb[0].length,
            stale: false
          } satisfies AgentEvidence
        }).pipe(
          // An unreadable chain must never take the listing page down, and must never let
          // it print a number it did not read. `stale` is the difference.
          Effect.catchAll(() =>
            Effect.succeed({ validationPasses: 0, validationsRead: 0, settlementFeedback: 0, stale: true } satisfies AgentEvidence)
          )
        )

        if (!result.stale) cache.set(agentId, { at: now(), value: result })
        return result
      })
  }
}

/**
 * The unarmed service.
 *
 * Present rather than absent on purpose: a hub with no ERC-8004 keys still answers
 * `/erc8004`, still renders listing pages, and still runs the queue — the queue simply gets
 * a refusal it already knows how to swallow. Making the tag optional instead would put a
 * null check at every call site, and the one that got forgotten would be the one that threw
 * inside the settlement path.
 */
export const noopErc8004 = (reason: string): Erc8004 => ({
  armed: false,
  addresses: { operator: "", validator: "", attester: "" },
  registries: { identity: "", reputation: "", validation: "" },
  ownerOf: () => new Erc8004Failed({ op: "ownerOf", reason }),
  requestValidation: () => new Erc8004Failed({ op: "validationRequest", reason }),
  respondValidation: () => new Erc8004Failed({ op: "validationResponse", reason }),
  giveFeedback: () => new Erc8004Failed({ op: "giveFeedback", reason }),
  evidenceFor: () => Effect.succeed({ validationPasses: 0, validationsRead: 0, settlementFeedback: 0, stale: true })
})

/**
 * Armed only when all three keys are present AND the chain manifest carries the registries
 * (`ChainConfig.erc8004`, Plan A Task 10). A hub missing any of them serves the whole
 * marketplace unchanged with no ERC-8004 surface, which is what "best-effort side effect"
 * has to mean at the layer level too.
 */
export const Erc8004FromEnv = (registries?: { identity: string; reputation: string; validation: string }): Layer.Layer<Erc8004Tag> => {
  const keys = {
    operator: process.env["ARCADE_OPERATOR_KEY"],
    validator: process.env["ARCADE_VALIDATOR_KEY"],
    attester: process.env["ARCADE_ATTESTER_KEY"]
  }
  if (registries === undefined || keys.operator === undefined || keys.validator === undefined || keys.attester === undefined) {
    const reason = "ERC-8004 is not configured on this hub (needs ARCADE_OPERATOR_KEY, ARCADE_VALIDATOR_KEY, ARCADE_ATTESTER_KEY and a chain manifest with erc8004 registries)"
    console.warn(`[hub] ${reason}`)
    return Layer.succeed(Erc8004Tag, noopErc8004(reason))
  }

  const accounts = {
    operator: privateKeyToAccount(keys.operator as `0x${string}`),
    validator: privateKeyToAccount(keys.validator as `0x${string}`),
    attester: privateKeyToAccount(keys.attester as `0x${string}`)
  }
  const refusal = keyRoleRefusal({
    operator: accounts.operator.address,
    validator: accounts.validator.address,
    attester: accounts.attester.address
  })
  if (refusal !== undefined) {
    // Refuse the FEATURE, not the hub: settlement does not depend on this, and taking the
    // marketplace down over an attestation misconfiguration would invert the priority.
    console.error(`[hub] ERC-8004 disabled — ${refusal}`)
    return Layer.succeed(Erc8004Tag, noopErc8004(refusal))
  }

  const chain = { id: ARC_CHAIN_ID, name: "Arc testnet", nativeCurrency: { name: "USDC", symbol: "USDC", decimals: 18 }, rpcUrls: { default: { http: [ARC_RPC_URL] } } } as const
  const transport = http(process.env["ARCADE_RPC_URL"] ?? ARC_RPC_URL, { retryCount: 3, retryDelay: 1000 })
  const pub = createPublicClient({ chain, transport })

  const walletFor = (account: ReturnType<typeof privateKeyToAccount>): Erc8004Wallet => {
    const w = createWalletClient({ account, chain, transport })
    return {
      address: account.address,
      writeContract: async (args) => {
        const hash = await w.writeContract({ ...(args as Record<string, never>), account, chain })
        // One receipt read per tick, never `waitForTransactionReceipt`: that helper polls
        // hard enough to earn `-32011 request limit reached` from Arc's public RPC.
        await Effect.runPromise(
          Effect.tryPromise(() => pub.getTransactionReceipt({ hash })).pipe(
            Effect.retry({ schedule: Schedule.spaced(`${RECEIPT_POLL_INTERVAL_MS} millis`).pipe(Schedule.compose(Schedule.recurs(40))) }),
            Effect.catchAll(() => Effect.void)
          )
        )
        return hash
      }
    }
  }

  console.log(
    `[hub] ERC-8004 armed — operator ${accounts.operator.address}, validator ${accounts.validator.address}, attester ${accounts.attester.address}`
  )
  return Layer.succeed(
    Erc8004Tag,
    makeErc8004({
      registries,
      chainId: ARC_CHAIN_ID,
      reader: pub as unknown as Erc8004Reader,
      operator: walletFor(accounts.operator),
      validator: walletFor(accounts.validator),
      attester: walletFor(accounts.attester)
    })
  )
}

```ts
import { Data, Effect, Schedule } from "effect"
import { createPublicClient, createWalletClient, http, parseEventLogs } from "viem"
import { privateKeyToAccount } from "viem/accounts"
import { ARC_RPC_URL, IDENTITY_REGISTRY_ABI, RECEIPT_POLL_INTERVAL_MS } from "@arcade/core"

/**
 * The seller's on-chain identity — minted on the seller's own machine, by the seller's own
 * key.
 *
 * This is the same boundary as everything else in the runner: the hub receives outputs and
 * public projections, never a key. An identity minted by the hub on a seller's behalf would
 * be an identity the hub could move, and `ownerOf` would name the wrong party — the exact
 * failure ERC-8004 exists to prevent.
 *
 * The seller pays gas here, and on Arc gas IS USDC — the same 0x3600… address, in 18
 * decimals rather than the 6 used for prices. So a seller who has settled at least one job
 * already holds gas, and one who has not gets a refusal that says so rather than a revert
 * from the RPC.
 */

export class UnfundedSeller extends Data.TaggedError("UnfundedSeller")<{
  readonly address: string
  readonly balanceWei: bigint
}> {}

export class IdentityFailed extends Data.TaggedError("IdentityFailed")<{
  readonly op: string
  readonly reason: string
}> {}

export interface IdentityClient {
  readonly address: string
  getBalance(a: { address: string }): Promise<bigint>
  writeContract(args: unknown): Promise<string>
  getTransactionReceipt(a: { hash: string }): Promise<{ status: string; logs: ReadonlyArray<unknown> }>
  readContract(args: unknown): Promise<unknown>
}

/**
 * 0.05 USDC in 18-decimal native units.
 *
 * Circle documents Arc gas at roughly 0.006 USDC per transaction, and registration is two
 * of them (`register`, then `setApprovalForAll`). Ten transactions of headroom is small
 * enough that a settled seller always clears it and large enough that nobody discovers the
 * shortfall halfway through, holding an agent id with no operator approval.
 */
export const MIN_GAS_WEI = 50_000_000_000_000_000n

const rpcRetry = Schedule.exponential("750 millis").pipe(Schedule.jittered, Schedule.compose(Schedule.recurs(4)))

export const gasCheck = (client: IdentityClient, address: string) =>
  Effect.gen(function* () {
    const balanceWei = yield* Effect.tryPromise({
      try: () => client.getBalance({ address }),
      catch: (e) => new IdentityFailed({ op: "getBalance", reason: String((e as Error)?.message ?? e) })
    }).pipe(Effect.catchTag("IdentityFailed", () => Effect.succeed(MIN_GAS_WEI)))
    // An unreadable balance is not evidence of an empty one: refusing a seller for someone
    // else's RPC outage is the wrong trade, and the transaction itself will say so if it
    // genuinely cannot pay.
    if (balanceWei < MIN_GAS_WEI) return yield* new UnfundedSeller({ address, balanceWei })
  })

/** The minted id, from `Registered` if the registry emitted it, else from the ERC-721 `Transfer`. */
export const agentIdFromLogs = (logs: ReadonlyArray<unknown>, owner: string): string | undefined => {
  const registered = parseEventLogs({ abi: IDENTITY_REGISTRY_ABI, eventName: "Registered", logs: logs as never })
  const mine = registered.find((l) => String(l.args.owner).toLowerCase() === owner.toLowerCase())
  if (mine !== undefined) return String(mine.args.agentId)
  const transfers = parseEventLogs({ abi: IDENTITY_REGISTRY_ABI, eventName: "Transfer", logs: logs as never })
  const mint = transfers.find((l) => String(l.args.to).toLowerCase() === owner.toLowerCase())
  return mint === undefined ? undefined : String(mint.args.tokenId)
}

const awaitReceipt = (client: IdentityClient, op: string, hash: string) =>
  // One read per tick. `waitForTransactionReceipt` polls hard enough to earn
  // `-32011 request limit reached` from Arc's public RPC — measured, not theoretical.
  Effect.tryPromise({
    try: () => client.getTransactionReceipt({ hash }),
    catch: (e) => new IdentityFailed({ op, reason: String((e as Error)?.message ?? e) })
  }).pipe(
    Effect.retry({ schedule: Schedule.spaced(`${RECEIPT_POLL_INTERVAL_MS} millis`).pipe(Schedule.compose(Schedule.recurs(40))) }),
    Effect.flatMap((r) =>
      r.status === "success"
        ? Effect.succeed(r)
        : new IdentityFailed({ op, reason: `transaction ${hash} reverted` })
    )
  )

export const registerAgent = (a: { client: IdentityClient; registry: string; agentURI: string }) =>
  Effect.gen(function* () {
    yield* gasCheck(a.client, a.client.address)
    const txHash = yield* Effect.tryPromise({
      try: () =>
        a.client.writeContract({
          address: a.registry,
          abi: IDENTITY_REGISTRY_ABI,
          functionName: "register",
          args: [a.agentURI]
        }),
      catch: (e) => new IdentityFailed({ op: "register", reason: String((e as Error)?.message ?? e) })
    }).pipe(Effect.retry({ schedule: rpcRetry, while: (e) => e.reason.includes("-32011") || e.reason.includes("request limit") }))

    const receipt = yield* awaitReceipt(a.client, "register", txHash)
    const agentId = agentIdFromLogs(receipt.logs, a.client.address)
    if (agentId === undefined) {
      return yield* new IdentityFailed({
        op: "register",
        reason: `${txHash} confirmed but emitted no Registered or Transfer log for ${a.client.address} — the address at ${a.registry} may not be an ERC-8004 IdentityRegistry`
      })
    }
    return { agentId, txHash }
  })

/**
 * Approve the hub's operator once, for every agent this seller owns.
 *
 * `setApprovalForAll` rather than a per-token approval because the standing being granted is
 * "may open validation requests for my agents", and it is granted to ONE named address the
 * seller can revoke in a single transaction. It does not let the operator move the token in
 * ARCADE's flow — nothing in this plan calls `transferFrom` — but it is a real ERC-721
 * approval and the CLI says so out loud before asking for it.
 */
export const approveOperator = (a: { client: IdentityClient; registry: string; operator: string }) =>
  Effect.gen(function* () {
    const already = yield* Effect.tryPromise({
      try: () =>
        a.client.readContract({
          address: a.registry,
          abi: IDENTITY_REGISTRY_ABI,
          functionName: "isApprovedForAll",
          args: [a.client.address, a.operator]
        }) as Promise<boolean>,
      catch: (e) => new IdentityFailed({ op: "isApprovedForAll", reason: String((e as Error)?.message ?? e) })
    })
    if (already) return { txHash: "", alreadyApproved: true }

    const txHash = yield* Effect.tryPromise({
      try: () =>
        a.client.writeContract({
          address: a.registry,
          abi: IDENTITY_REGISTRY_ABI,
          functionName: "setApprovalForAll",
          args: [a.operator, true]
        }),
      catch: (e) => new IdentityFailed({ op: "setApprovalForAll", reason: String((e as Error)?.message ?? e) })
    })
    yield* awaitReceipt(a.client, "setApprovalForAll", txHash)
    return { txHash, alreadyApproved: false }
  })

import { HEARTBEAT_INTERVAL_MS, HEARTBEAT_MISS_LIMIT, buildAgentRegistration, type AgentRegistrationDoc } from "@arcade/core"
import type { ListingRecord, RunnerRecord } from "./store.ts"

/**
 * `active` is derived from the heartbeat, not stored.
 *
 * The registration file is the thing another agent reads before hiring, so "active" has to
 * mean "a runner is serving this right now" — the same fact `/listings` is built from. A
 * stored boolean would go stale exactly when a runner dies, which is the moment it matters.
 */
export const agentRegistrationFor = (a: {
  rec: ListingRecord
  runner: RunnerRecord | undefined
  origin: string
  chainId: number
  identityRegistry: string
  nowMs: number
}): AgentRegistrationDoc =>
  buildAgentRegistration({
    origin: a.origin,
    skillId: a.rec.listing.id,
    serviceName: a.rec.listing.serviceName,
    description: a.rec.listing.description,
    seller: a.rec.seller,
    chainId: a.chainId,
    identityRegistry: a.identityRegistry,
    active:
      a.runner !== undefined && a.nowMs - a.runner.lastSeenMs < HEARTBEAT_INTERVAL_MS * HEARTBEAT_MISS_LIMIT,
    ens: a.rec.ensName
  })
```

export interface HubErc8004 {
  readonly armed: boolean
  readonly registries?: { identity: string; reputation: string; validation: string }
  readonly operator?: string
  readonly validator?: string
  readonly attester?: string
  readonly caip2?: string

/** Why this hub cannot be registered against. `undefined` means it can. */
export const hubErc8004Refusal = (h: unknown, hubUrl: string): string | undefined => {
  if (typeof h !== "object" || h === null || !("armed" in h)) {
    return `${hubUrl}/erc8004 did not answer with an ERC-8004 document. Check the hub url in ~/.arcade/config.json, or that the hub is running a build with ERC-8004 support.`
  }
  const doc = h as HubErc8004
  if (!doc.armed) {
    return `${hubUrl} is not running ERC-8004 — it has no operator, validator or attester key configured, so there is nothing to approve and nothing would attest your jobs. Nothing has been registered.`
  }
  if (doc.registries === undefined) return `${hubUrl} reported ERC-8004 armed but named no registries.`
  if (doc.operator === undefined || doc.operator === "") {
    return `${hubUrl} reported ERC-8004 armed but named no operator address, so there is no address to approve.`
  }
  return undefined
}

export const skillRefusal = (skillId: string, known: ReadonlyArray<string>): string | undefined =>
  known.includes(skillId)
    ? undefined
    : `no skill "${skillId}" on this machine.\n\n  available: ${known.length === 0 ? "(none — is --skills pointing at the right directory?)" : known.join(", ")}`

 * The unfunded refusal.
 *
 * Balance is printed in USDC at 18 decimals because that is what gas is denominated in on
 * Arc — the SAME token as the price, at a different scale. Printing raw wei would look like
 * a different asset, and printing it at 6 would be off by a factor of a trillion.
 */

  `  needed    ${formatUnits(MIN_GAS_WEI, 18)} USDC (two transactions: register, then setApprovalForAll)\n\n` +
  `Gas on Arc is USDC — the same token you are paid in, so a seller who has settled even one\n` +
  `job already holds enough. If this address has never been paid, fund it once:\n\n  ${faucet}\n\n` +
  `Nothing was broadcast; your identity is unchanged.`

- [ ] **Step 6: Implement `verifyAgentClaims` in `apps/hub/src/erc8004.ts`**

```ts
import type { AgentAnnouncement } from "@arcade/core"

/**
 * A claimed agent id is worth exactly what the registry says it is.
 *
 * Three outcomes, and the difference between them is the point:
 *  - the chain names this seller  → kept, `agentVerified: true`
 *  - the chain names someone else → DROPPED. Announcing another party's agent id would
 *    hang their validation history off your listing, which is the reputation equivalent of
 *    the payout-redirection attack the `Hello` signature exists to stop.
 *  - the chain could not be read  → kept, `agentVerified: false`. Refusing a seller for an
 *    RPC outage is the wrong trade (the same fail-open as `splitterVerified`), and the page
 *    says the claim is unverified rather than showing it as checked.
 */
export const verifyAgentClaims = (
  erc8004: Erc8004,
  seller: string,
  claims: ReadonlyArray<AgentAnnouncement>
): Effect.Effect<ReadonlyMap<string, { agentId: string; registrationTx: string; agentVerified: boolean }>> =>
  Effect.gen(function* () {
    const out = new Map<string, { agentId: string; registrationTx: string; agentVerified: boolean }>()
    if (!erc8004.armed) return out
    for (const claim of claims) {
      const owner = yield* Effect.either(erc8004.ownerOf(claim.agentId))
      if (owner._tag === "Left") {
        out.set(claim.skillId, { agentId: claim.agentId, registrationTx: claim.registrationTx, agentVerified: false })
        continue
      }
      if (owner.right.toLowerCase() !== seller.toLowerCase()) {
        console.error(
          `[hub] dropping agent claim: ${seller} announced agent ${claim.agentId} for ${claim.skillId}, ` +
            `but IdentityRegistry.ownerOf says ${owner.right}`
        )
        continue
      }
      out.set(claim.skillId, { agentId: claim.agentId, registrationTx: claim.registrationTx, agentVerified: true })
    }
    return out
  })
```

```ts
import { Context, Effect, Layer, Queue, Ref, Schedule } from "effect"
import {
  buildFeedback,
  buildValidationRequest,
  buildValidationResponse,
  docHash,
  feedbackUrl,
  validationRequestUrl,
  validationResponseUrl
} from "@arcade/core"
import { Erc8004Tag, type Erc8004 } from "./erc8004.ts"

/**
 * ERC-8004 attestation, downstream of settlement and unable to touch it.
 *
 * The whole product guarantee is "settle only on success, and never broadcast on failure".
 * Three registry writes per job are three more chances to throw, hang on a rate-limited RPC,
 * or revert — so none of them happens on the path that decides a receipt. `onTerminal`
 * offers to a queue and returns; a background fiber does the writing; every failure is
 * logged and dropped.
 *
 * The queue is DROPPING rather than unbounded: a hub that cannot reach the chain for an hour
 * should lose attestations, not memory. Losing one is recoverable (the receipt is still the
 * evidence, and the chain is still missing a row anyone can see is missing); an OOM during a
 * demo is not.
 */

export interface AttestJob {
  readonly jobId: string
  readonly agentId?: string | undefined
  readonly skillId: string
  readonly skillVersion: string
  readonly seller: string
  readonly buyer: string
  /** Where the settlement actually paid: the splitter when there is one, else the seller. */
  readonly payTo: string
  readonly origin: string
  readonly input: unknown
  readonly output: unknown
  readonly outputSchema: unknown
  readonly status: string
  readonly stopReason?: string | undefined
  readonly settled: boolean
  readonly reason: string
  readonly priceAtomic: bigint
  readonly settleTx?: string | undefined
  readonly createdAtMs: number
  readonly chainId: number
  readonly identityRegistry: string
}

export interface AttestOutcome {
  readonly skipped?: string
  readonly requestTx?: string
  readonly responseTx?: string
  readonly feedbackTx?: string
  readonly errors: ReadonlyArray<string>
}

export interface Attest {
  readonly onTerminal: (job: AttestJob) => Effect.Effect<void>
  /** Resolves when the queue is empty and no job is in flight. For tests and shutdown. */
  readonly idle: Effect.Effect<void>
}

export class AttestTag extends Context.Tag("@arcade/hub/Attest")<AttestTag, Attest>() {}

/** One retry. Two attempts is enough for a nonce race or a flaky RPC; more is a queue that never empties. */
const ONE_RETRY = Schedule.recurs(1)
const QUEUE_CAPACITY = 512

export const processOne = (erc8004: Erc8004, job: AttestJob): Effect.Effect<AttestOutcome> =>
  Effect.gen(function* () {
    if (!erc8004.armed) return { skipped: "hub is not armed for ERC-8004", errors: [] }
    if (job.agentId === undefined) {
      return { skipped: `no agent registered for ${job.skillId}`, errors: [] }
    }
    const agentId = job.agentId
    const errors: Array<string> = []

    const requestDoc = buildValidationRequest({
      origin: job.origin,
      jobId: job.jobId,
      agentId,
      skillId: job.skillId,
      skillVersion: job.skillVersion,
      input: job.input,
      output: job.output,
      outputSchema: job.outputSchema,
      status: job.status,
      stopReason: job.stopReason,
      settled: job.settled,
      reason: job.reason,
      priceAtomic: job.priceAtomic,
      settleTx: job.settleTx,
      createdAtMs: job.createdAtMs
    })
    const requestHash = docHash(requestDoc)

    const request = yield* Effect.either(
      erc8004
        .requestValidation({ agentId, requestURI: validationRequestUrl(job.origin, job.jobId), requestHash })
        .pipe(Effect.retry(ONE_RETRY))
    )
    if (request._tag === "Left") {
      // No response without a request: the registry keys the response on `requestHash`, and
      // answering a request that never landed would revert every time.
      errors.push(`validationRequest: ${request.left.reason}`)
      return { errors }
    }

    const responseDoc = buildValidationResponse({
      jobId: job.jobId,
      requestHash,
      settled: job.settled,
      reason: job.reason,
      decidedAtMs: job.createdAtMs
    })
    const response = yield* Effect.either(
      erc8004
        .respondValidation({
          requestHash,
          response: responseDoc.response,
          responseURI: validationResponseUrl(job.origin, job.jobId),
          responseHash: docHash(responseDoc)
        })
        .pipe(Effect.retry(ONE_RETRY))
    )
    if (response._tag === "Left") errors.push(`validationResponse: ${response.left.reason}`)

    // Feedback ONLY on a settled receipt with a transaction to point at. Vouching for an
    // unsettled job would be vouching for a payment that never happened, and the whole value
    // of `proofOfPayment` is that it names one that did.
    if (!job.settled || job.settleTx === undefined) {
      return {
        requestTx: request.right,
        ...(response._tag === "Right" ? { responseTx: response.right } : {}),
        errors
      }
    }

    const feedbackDoc = buildFeedback({
      origin: job.origin,
      jobId: job.jobId,
      agentId,
      skillId: job.skillId,
      seller: job.seller,
      buyer: job.buyer,
      payTo: job.payTo,
      settleTx: job.settleTx,
      chainId: job.chainId,
      identityRegistry: job.identityRegistry,
      attester: erc8004.addresses.attester,
      createdAtMs: job.createdAtMs
    })
    const feedback = yield* Effect.either(
      erc8004
        .giveFeedback({
          agentId,
          skillId: job.skillId,
          endpoint: feedbackDoc.endpoint,
          feedbackURI: feedbackUrl(job.origin, job.jobId),
          feedbackHash: docHash(feedbackDoc)
        })
        .pipe(Effect.retry(ONE_RETRY))
    )
    if (feedback._tag === "Left") errors.push(`giveFeedback: ${feedback.left.reason}`)

    return {
      requestTx: request.right,
      ...(response._tag === "Right" ? { responseTx: response.right } : {}),
      ...(feedback._tag === "Right" ? { feedbackTx: feedback.right } : {}),
      errors
    }
  })

export const makeAttest = (erc8004: Erc8004): Effect.Effect<Attest, never, never> =>
  Effect.gen(function* () {
    const queue = yield* Queue.dropping<AttestJob>(QUEUE_CAPACITY)
    const inFlight = yield* Ref.make(0)

    const worker = Effect.gen(function* () {
      const job = yield* Queue.take(queue)
      yield* Ref.update(inFlight, (n) => n + 1)
      const out = yield* processOne(erc8004, job)
      yield* Ref.update(inFlight, (n) => n - 1)
      if (out.skipped === undefined) {
        console.log(
          `[hub] erc8004 ${job.jobId} agent=${job.agentId} ` +
            `request=${out.requestTx ?? "-"} response=${out.responseTx ?? "-"} feedback=${out.feedbackTx ?? "-"}` +
            (out.errors.length === 0 ? "" : ` errors=${out.errors.join("; ")}`)
        )
      }
    }).pipe(
      // A worker that dies takes every later attestation with it. Nothing here may kill it.
      Effect.catchAllCause((cause) => Effect.sync(() => console.error(`[hub] erc8004 worker: ${String(cause)}`))),
      Effect.forever
    )

    yield* Effect.forkScoped(worker)

    return {
      onTerminal: (job) =>
        Effect.gen(function* () {
          const accepted = yield* Queue.offer(queue, job)
          if (!accepted) console.warn(`[hub] erc8004 queue full — dropped attestation for ${job.jobId}`)
        }),
      idle: Effect.gen(function* () {
        yield* Effect.repeat(Effect.void, {
          while: () =>
            Effect.map(
              Effect.all([Queue.size(queue), Ref.get(inFlight)]),
              ([size, n]) => size > 0 || n > 0
            ),
          schedule: Schedule.spaced("5 millis")
        })
      })
    }
  })

export const AttestLive: Layer.Layer<AttestTag, never, Erc8004Tag> = Layer.scoped(
  AttestTag,
  Effect.flatMap(Erc8004Tag, makeAttest)
)
```

**Why the bytes are stored rather than rebuilt.** The registries hold `keccak256` of a document beside its URI, and the only reason that pair is worth anything is that a reader can fetch the URI and check the hash. Rebuilding on demand would depend on a listing that only exists while a runner is connected — kill the runner and every committed URI would 404 or, worse, render with a different `outputSchema` and hash differently. Storing the exact bytes at the moment they were hashed makes the commitment permanent, which is the whole claim.

**What it proves.** That the three registries were exercised by three different keys against a real job on Arc testnet, and that the feedback names the settlement transaction of that job. Nothing in the script fakes a step: every hash it prints comes out of the hub's own log or the chain.

- [ ] **Step 1: Write the script**

```bash
#!/bin/bash
# ERC-8004 end-to-end on Arc testnet: identity, validation, and settlement feedback.
#
# One paid job produces four transactions from four different keys:
#   seller key     → IdentityRegistry.register          (Registered)
#   operator key   → ValidationRegistry.validationRequest
#   validator key  → ValidationRegistry.validationResponse  (ValidationResponse, response=100)
#   attester key   → ReputationRegistry.giveFeedback     (NewFeedback, proofOfPayment = the settle tx)
#
# The separation is the point: ERC-8004 forbids an agent's owner or operator from writing its
# own feedback, so a single-key demo cannot exist. Every hash below is read back from the log
# the hub wrote or from the chain — nothing is asserted.
#
#   ARCADE_FACILITATOR_KEY   funded Arc testnet key, broadcasts settlements
#   ARCADE_BUYER_KEY         funded Arc testnet key, pays for the job
#   ARCADE_SELLER_KEY        funded Arc testnet key, OWNS the agent (needs ~0.05 USDC for gas)
#   ARCADE_OPERATOR_KEY      hub key, approved by the seller
#   ARCADE_VALIDATOR_KEY     hub key, answers validations
#   ARCADE_ATTESTER_KEY      hub key, writes feedback — must be neither owner nor operator
#
# usage:
#   ARCADE_FACILITATOR_KEY=0x… ARCADE_BUYER_KEY=0x… ARCADE_SELLER_KEY=0x… \
#   ARCADE_OPERATOR_KEY=0x… ARCADE_VALIDATOR_KEY=0x… ARCADE_ATTESTER_KEY=0x… \
#   bash scripts/e2e-erc8004.sh
set -eu

: "${ARCADE_FACILITATOR_KEY:?set a funded Arc testnet key for the facilitator}"
: "${ARCADE_BUYER_KEY:?set a funded Arc testnet key for the buyer}"
: "${ARCADE_SELLER_KEY:?set a funded Arc testnet key for the seller (it owns the agent)}"
: "${ARCADE_OPERATOR_KEY:?set the hub operator key}"
: "${ARCADE_VALIDATOR_KEY:?set the hub validator key}"
: "${ARCADE_ATTESTER_KEY:?set the hub attester key}"

PORT="${PORT:-8792}"
HUB="http://localhost:$PORT"
SKILL="${SKILL:-usdc-flow-check}"
INPUT="${INPUT:-{\"address\":\"0xAeB742d58cc7F5CF656fCD9Beb07Bf0C1ACa6f5b\"}}"
EXPLORER="https://testnet.arcscan.app"
HUB_LOG=$(mktemp)
RUNNER_LOG=$(mktemp)
ARCADE_HOME=$(mktemp -d)

cleanup() {
  kill ${RUNNER_PID:-0} ${HUB_PID:-0} 2>/dev/null || true
}
trap cleanup EXIT

SELLER=$(bun -e 'import {privateKeyToAccount} from "viem/accounts"; console.log(privateKeyToAccount(process.env.ARCADE_SELLER_KEY).address)')

echo "== hub with all three ERC-8004 keys =="
ARCADE_RAIL=eip3009 PORT=$PORT ARCADE_DB="$ARCADE_HOME/hub.sqlite" \
  bun run apps/hub/src/server.ts > "$HUB_LOG" 2>&1 &
HUB_PID=$!
sleep 3
curl -sf "$HUB/healthz" > /dev/null
curl -s "$HUB/erc8004" | bun -e '
  const d = await Bun.stdin.json()
  if (!d.armed) { console.error("hub reports ERC-8004 unarmed — check the three keys"); process.exit(1) }
  console.log(`  operator  ${d.operator}\n  validator ${d.validator}\n  attester  ${d.attester}`)
  console.log(`  identity  ${d.registries.identity}\n  reputation ${d.registries.reputation}\n  validation ${d.registries.validation}`)
'

echo
echo "== seller registers its agent (seller key, on chain) =="
HOME="$ARCADE_HOME" bun run packages/runner/src/cli.ts init --seller "$SELLER" --hub "$HUB" > /dev/null
REGISTER_OUT=$(HOME="$ARCADE_HOME" bun run packages/runner/src/cli.ts identity register "$SKILL" 2>&1) || {
  echo "$REGISTER_OUT"; exit 1
}
echo "$REGISTER_OUT"
AGENT_ID=$(HOME="$ARCADE_HOME" bun -e '
  const cfg = await Bun.file(`${process.env.HOME}/.arcade/config.json`).json()
  console.log(cfg.agents[process.env.SKILL].agentId)
' SKILL="$SKILL")
REGISTER_TX=$(HOME="$ARCADE_HOME" bun -e '
  const cfg = await Bun.file(`${process.env.HOME}/.arcade/config.json`).json()
  console.log(cfg.agents[process.env.SKILL].registrationTx)
' SKILL="$SKILL")

echo
echo "== runner announces the agent =="
HOME="$ARCADE_HOME" bun run packages/runner/src/cli.ts start > "$RUNNER_LOG" 2>&1 &
RUNNER_PID=$!
sleep 4
grep -q "agents=\[" "$HUB_LOG" || { echo "hub never saw the agent announcement"; tail -20 "$HUB_LOG"; exit 1; }

echo
echo "== one paid job =="
ARCADE_HUB="$HUB" bun run packages/buyer/src/cli.ts "$SKILL" --input "$INPUT" --max-amount 0.10

echo
echo "== the queue's three writes =="
for i in $(seq 1 40); do
  LINE=$(grep -m1 "erc8004 job_" "$HUB_LOG" || true)
  [ -n "$LINE" ] && break
  sleep 2
done
[ -n "${LINE:-}" ] || { echo "no attestation line in the hub log"; tail -30 "$HUB_LOG"; exit 1; }
echo "$LINE"
RESPONSE_TX=$(echo "$LINE" | sed -n 's/.*response=\([^ ]*\).*/\1/p')
FEEDBACK_TX=$(echo "$LINE" | sed -n 's/.*feedback=\([^ ]*\).*/\1/p')
JOB_ID=$(echo "$LINE" | sed -n 's/.*erc8004 \(job_[A-Za-z0-9_]*\).*/\1/p')

echo
echo "== read back from the chain, not from our own log =="
curl -s "$HUB/receipts/$JOB_ID/feedback.json" | bun -e '
  const doc = await Bun.stdin.json()
  console.log(`  feedback file      value=${doc.value} tag1=${doc.tag1} tag2=${doc.tag2}`)
  console.log(`  proofOfPayment     ${doc.proofOfPayment.txHash} (${doc.proofOfPayment.fromAddress} → ${doc.proofOfPayment.toAddress})`)
'
curl -s "$HUB/listings/$SKILL" | bun -e '
  const d = await Bun.stdin.json()
  const e = d.erc8004
  if (e === undefined) { console.error("  listing reports no ERC-8004 evidence"); process.exit(1) }
  console.log(`  agent              #${e.agentId} owner-verified=${e.verified}`)
  console.log(`  validations passed ${e.validationPasses ?? "?"} of ${e.validationsRead ?? "?"}`)
  console.log(`  settlements vouched ${e.settlementFeedback ?? "?"}`)
'

SETTLE_TX=$(curl -s "$HUB/receipts/$JOB_ID/feedback.json" | bun -e 'console.log((await Bun.stdin.json()).proofOfPayment.txHash)')

cat <<EOF

────────────────────────────────────────────────────────────────
ERC-8004 on Arc testnet — agent #$AGENT_ID for "$SKILL"

  Registered          $EXPLORER/tx/$REGISTER_TX
  ValidationResponse  $EXPLORER/tx/$RESPONSE_TX
  NewFeedback         $EXPLORER/tx/$FEEDBACK_TX
  settlement it vouches for
                      $EXPLORER/tx/$SETTLE_TX

  registration file   $HUB/listings/$SKILL/agent-registration.json
  validation request  $HUB/receipts/$JOB_ID/validation-request.json
  feedback file       $HUB/receipts/$JOB_ID/feedback.json
────────────────────────────────────────────────────────────────
EOF
```
